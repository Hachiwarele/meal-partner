# MEAL PARTNER 🌱

食事・体重・栄養バランスを手軽に記録できる、スマートフォン向けの個人用Webアプリです。

## 公開ページ
https://hachiwarele.github.io/meal-partner/

## v3 の使い方
1. **食事を記録**：食品検索／自由入力／お気に入り／写真添付に対応。食品検索には野菜・きのこ・海藻・いも類・調味料・肉・パン・おにぎり・お茶など約186品を収録しています。食品の栄養値は参考値・概算値を含みます。
2. **履歴**：一覧では日付ごとにまとめて表示。その日の昼食・夕食・間食は従来どおり個別に保存されます。写真を含め、過去の食事データは変更・削除しません。
3. **AIに相談**：ホーム画面で「未計算だけ／その日の記録／直近7日」から目的を選び、「プロンプトをコピー」を押してChatGPTに貼り付けます。AIの応答には `meal-partner-ai-v1` 形式のJSONコードブロックを含めるよう依頼します。
4. **AI結果を取り込む**：JSONコードブロックをホーム画面の「AI補完・アドバイス保存」に貼り、「自動反映」を押します。食品ID・日付・名前を照合して、**未計算の栄養素だけ**を補完。すでにある栄養値は原則上書きしません。AIのアドバイスは日別履歴に保存されます。
5. **マイ食品辞典**：AI補完した食品は自動で保存されます。「設定」の食品辞典から検索・編集・削除できます。保存後の修正は過去の食事に遡って自動適用されません。
6. **間違った場合**：「直前のAI補完を取り消す」を押すと、その補完による変更を原則として戻せます。補完後に個別編集した値は上書きしない設計です。

## 保存とバックアップ
- 食事・写真・体重・お気に入り・個人設定は**ブラウザ内のIndexedDB**に保存されます。v3の更新は既存データベースの内容を削除せず、新しい保存領域を追加する方式です。
- v3では新しく「マイ食品辞典」「AIアドバイス」「補完の取り消し記録」が増えます。
- **更新前後に必ず「設定 → バックアップ → 保存」でJSONを保存**してください。Safariなどのサイトデータを消去すると、アプリの記録も失われる可能性があります。GitHubに記録を保存する機能ではありません。
- 旧形式（version 1）のバックアップも復元できます。v3バックアップ（version 2）は新しい記録領域も含みます。
- 別端末との自動同期やAI APIによる自動通信には**対応していません**。AIへの相談と結果の取り込みは利用者がコピー／貼り付けする方式です。

## 栄養値について
- 一般的な食品の数値は概算であり、商品・調理法・品種によって異なります。商品ラベルがある場合はラベル値を優先してください。
- 肉の重量は加熱前で記録し、皮・骨込み重量や使用した油・調味料にも注意してください。
- 食品が未計算の場合はゼロカロリーとみなさず、合計値に「＋」または未計算の案内を表示します。
- このアプリは医療診断や治療を目的とするものではありません。


## ☁️ メールなしクラウド同期（準備ブランチ / 未公開）

**いまのGitHub Pages公開版（main）にはクラウド機能を反映していません。** 実機で検証後に公開するまで、食事・写真・体重はiPhone内のIndexedDBに残ります。公開版コードの保存用ブランチ：`backup/pre-firebase-cloud-2026-11`。

### 必ず最初にバックアップする
1. 食事履歴が残っているSafari版のMEAL PARTNERを開く
2. **設定 → バックアップ → 保存**を押す
3. iPhoneの「ファイル」アプリでJSONファイルが開けることを確認し、可能ならiCloud Driveにも保存
4. JSONには健康に関わる食事・体重・設定・写真が含まれるため、公開GitHubにはコミットしない
5. **SafariのWebサイトデータ・ホーム画面アプリ・ローカルデータを削除しない**

### Firebase Consoleでユーザーが設定するもの
1. FirebaseプロジェクトのWebアプリ（`</>`アイコン）を追加し、`firebaseConfig`を取得。公開用設定をこのブランチの`firebase-config.js`へ入力
2. Firebase Authentication → **Sign-in method → 匿名（Anonymous）を有効**にする。メール/パスワード方式は不要
3. Realtime Databaseを**ロックモード**で作成する。ルール画面へこのブランチの`firebase-rules.json`全体を貼って**公開**
4. Realtime Databaseの正しい`databaseURL`が `firebaseConfig` にあることを確認
5. 準備完了後に動作検証する。検証前に`main`へは反映しない

### 利用方法
- 最初のSafari版で **「自分専用の部屋を作る」**。初回に**12文字の共有コード＋64桁の復旧キー**を発行する
- 復旧キーは自動で生成された**32バイト（256ビット）の乱数**。発行した内容を「コード＋復旧キーをコピー」で安全な場所に保存
- 「バックアップ保存済み」を確認して初回クラウド同期を開始。Firebase上でデータが保存されたことを確認
- iPhoneのホーム画面版では同じコードと復旧キーを入力して接続。「バックアップ保存済み」を確認して同期を開始
- この仕組みではメールアドレス不要。Firebaseの**匿名認証**は端末ごとに別のIDでよい。部屋の所有を判断するのは**共有コードと秘密の復旧キーを知っていること**であり、端末の匿名ユーザーIDは識別にのみ利用する
- キーを忘れたときのメールによる回復はない。**復旧キーとバックアップJSONを両方安全に保管**すること
- 復旧キーを他人に渡すとその人も記録を読める。共有する相手は信頼できる人だけにする
- 復旧キーそのものはFirebaseに送らず、部屋コードを含めてSHA-256化した照合値を**読み取り禁止領域**へ登録する。入室する端末は照合値の一致をサーバー側ルールで検証する
- 端末内のデータは残り、サーバーへの初回アップロードは**同じIDの既存クラウド記録を上書きしない**。重複競合は警告する
- Safariとホーム画面版の保存領域は別。**クラウド同期が有効になってから**記録を共有できるようになる
- Firebase容量・通信量は無料枠を超える場合がある。大量の写真は保存制限に注意

### セキュリティと既知の制約
- `mealPartnerRoomKeys/$roomId`は**読み取り禁止**（復旧キーの照合値の登録先）
- `mealPartnerRoomProofs/$roomId/$uid`には**一致を検証した端末のみ書き込み可**
- `mealPartnerRooms/$roomId/v1`の読み取りは、検証済みの匿名ユーザーに限る
- Firebase Rulesのテストを行う前に公開してはいけない。Cloud Syncは独立した機能ブランチに留める
- 複数端末で同じ食事を同時編集した場合の競合やブラウザ容量制限は、実機試験が必要。**バックアップが正式な復旧手段として重要**
