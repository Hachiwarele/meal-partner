# MEAL PARTNER 🌱

食事・体重・栄養バランスを手軽に記録できる、スマートフォン向けの個人用Webアプリです。

## 公開ページ
https://hachiwarele.github.io/meal-partner/

## v3 の使い方
1. **食事を記録**：食品検索／自由入力／お気に入り／写真添付に対応。食品検索には野菜・きのこ・海藻・いも類・調味料・肉・パン・おにぎり・お茶など約186品を収録しています。食品の栄養値は参考値・概算値を含みます。
2. **履歴**：一覧では日付ごとにまとめて表示。その日の昼食・夕食・間食は従来どおり個別に保存されます。写真を含め、過去の食事データは変更・削除しません。
3. **AIに相談**：ホーム画面で「未計算だけ／その日の記録／直近7日」から目的を選び、「プロンプトをコピー」を押してChatGPTに貼り付けます。AIの応答には `meal-partner-ai-v1` 形式のJSONコードブロックを含めるよう依頼します。
4. **AI結果を取り込む**：JSONコードブロックをホーム画面の「AI補完・アドバイス保存」に貼り、「自動反映」を押します。食品ID・日付・名前を照合して、**未計算の栄養素だけ**を補完。すでにある栄養値は原則上書きしません。AIのアドバイスは日別履歴に保存されます。
5. **マイ食品辞典**：AI補完した食品は自動で保存されます。「設定」の食品辞典から検索・編集・削除できます。保存後の修正は過去の食事に遡って自動適用されません。
6. **間違った場合**：「直前のAI補完を取り消す」を押すと、その補完による変更を原則として戻せます。補完後に個別編集した値は上書きしない設計です。

## 保存とバックアップ
- 食事・写真・体重・お気に入り・個人設定は**ブラウザ内のIndexedDB**に保存されます。v3の更新は既存データベースの内容を削除せず、新しい保存領域を追加する方式です。
- v3では新しく「マイ食品辞典」「AIアドバイス」「補完の取り消し記録」が増えます。
- **更新前後に必ず「設定 → バックアップ → 保存」でJSONを保存**してください。Safariなどのサイトデータを消去すると、アプリの記録も失われる可能性があります。GitHubに記録を保存する機能ではありません。
- 旧形式（version 1）のバックアップも復元できます。v3バックアップ（version 2）は新しい記録領域も含みます。
- 別端末との自動同期やAI APIによる自動通信には**対応していません**。AIへの相談と結果の取り込みは利用者がコピー／貼り付けする方式です。

## 栄養値について
- 一般的な食品の数値は概算であり、商品・調理法・品種によって異なります。商品ラベルがある場合はラベル値を優先してください。
- 肉の重量は加熱前で記録し、皮・骨込み重量や使用した油・調味料にも注意してください。
- 食品が未計算の場合はゼロカロリーとみなさず、合計値に「＋」または未計算の案内を表示します。
- このアプリは医療診断や治療を目的とするものではありません。


## 🔐 Cloud Sync v4（準備ブランチ / まだ公開版には未反映）

この機能は `feature/firebase-cloud-safe-sync` ブランチにあり、`main` にはまだ含まれていません。設定と実データの確認が終わるまでは公開しないでください。変更前の公開用コードは `backup/pre-firebase-cloud-2026-11` に保管しています。

### 最優先：Safari上の食事履歴のバックアップ
1. **現在の食事履歴が表示されるSafariのMEAL PARTNER**を開く。
2. **設定 → バックアップ → 保存**で `meal-partner-backup-YYYY-MM-DD.json` をダウンロード。
3. iPhoneの「ファイル」アプリでJSONが存在することを確認。可能ならiCloud Driveにもコピー。
4. ホーム画面版はSafariと保存領域が異なるため、ホーム画面版でゼロ件と表示されてもSafari側のサイトデータやアプリを削除しない。
5. **機種変更、Safariのサイトデータ削除、ホーム画面アプリの削除の前に、バックアップとクラウド側での復元確認をすること。**

ChatGPTやGitHubからSafari内部のIndexedDBデータ・写真を直接取得することはできません。ユーザー自身がJSONを書き出す必要があります。JSONには食事・写真・体重等が入っているため、GitHubの公開リポジトリへコミットしないでください。

### Firebase セットアップ（本人の操作が必要）
1. Firebase Consoleで**MEAL PARTNER専用**のプロジェクトを作成し、Webアプリを登録。
2. Authenticationで**メール/パスワード**を有効にする（iPhoneのSafariとホーム画面版で同じアカウントへログインするため）。パスワードはチャットで共有しない。
3. Realtime Databaseを作成し、**テストモードの公開ルールは使わず** `firebase-rules.json` の本人限定ルールを設定・公開する。
4. Webアプリの公開用Firebase設定を `firebase-config.js` に入力する。
5. Safari版で既存履歴のバックアップを保存し、ログイン→バックアップ確認チェック→初回クラウド同期を開始する。
6. Firebaseのデータに記録があるか確認してから、ホーム画面版で同じアカウントでログイン→初回同期を開始して復元確認。

### 保存方式
- 既存のIndexedDBを**消去・上書きせず**、バージョン2→3へのアップグレードで小さな `cloudOutbox` ストアを追加します。オフライン時の未送信操作を保持する目的です。
- 初回同期はローカルにある記録をFirebaseへ**既存クラウド記録を上書きしない形で追加**します。同一IDで内容が異なる場合は競合として残し、自動上書きしません。
- 食事・写真・体重・お気に入り・個人設定・AIアドバイス・マイ食品辞典・AI補完履歴を同期対象にします。写真はJPEG等のデータURLへ変換して保存します（上限あり）。
- 通常の追加/編集/削除はクラウドにも送信し、他のログイン済み端末でも反映します。ただし同時編集などは実機で検証してください。
- Cloud Syncの初期化に失敗した場合もローカル保存は継続します。**クラウド接続が成功したという表示が出るまでは、ローカルのバックアップを安全に保持してください。**
- Firebaseの無料枠を超えると同期できない可能性があります。同期用データの保存先・コストをFirebase Consoleで確認してください。

### セキュリティ
Realtime Databaseは `mealPartnerUsers/$uid/v1` 配下で、ログイン中の `auth.uid` が `$uid` と一致する場合のみアクセスを許可します。APIキー（公開設定）は秘密鍵ではありませんが、サービスアカウントJSONやパスワードはGitHubに絶対に登録しないでください。
